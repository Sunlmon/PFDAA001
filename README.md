# Creating Through Rules: Why I Still Need to Learn Programming

The internet has continually expanded the boundaries of art and given designers more tools and media through which to create. Art is no longer limited to painting, sculpture, or photography. It can also take the form of moving images, interactive installations, generative graphics, or even a program while it is running. For this reason, I believe that learning programming as a designer is not only about gaining a practical skill. It is also about understanding a new creative medium.

Several years ago, while scrolling through a video platform, I encountered an animated work that combined a web-like structure with typography. The letters moved, changed, and interacted with lines and space. I no longer remember the title or the artist, but I still remember my reaction to it. I was curious about which software had been used to create the effect. Someone in the comments explained that it had been generated with code.

That moment challenged my previous understanding of programming. I had imagined code as something completely rational, technical, and closely associated with engineering. However, the work showed me that code could also produce visual expression. It simply approached creation through a more logical and rule-based process. Instead of manually deciding every final image, an artist could define how letters move, how lines connect, how forms respond to time, and how the work changes through interaction.

## Creativity Within Constraints

Art and programming may have more in common than they first appear to. Programming languages operate through strict syntax and logical constraints. Designers also work within limitations such as dimensions, materials, software capabilities, brand guidelines, budgets, and user needs. These limitations do not necessarily reduce creativity. Understanding and reorganising them can lead to new forms of expression.

In [*The Art of Code*](https://www.youtube.com/watch?v=6avJHaC3C2U), Dylan Beattie presents programming as more than a practical method for producing functional software. Through examples including Conway’s Game of Life, quines, obfuscated code, esoteric programming languages, visual programs, and algorithmic music, he demonstrates how rules, syntax, constraints, and execution can become materials for creative expression (NDC Conferences, 2020).

For example, a program written in Piet can resemble an abstract painting. A Chef program can also be read as a recipe, while Beattie’s own Rockstar language allows executable programs to resemble rock lyrics. These examples blur the distinction between a tool, an artwork, and the process used to produce it.

Beattie’s talk does not prove that every piece of code is art. Instead, it demonstrates that code has the potential to become an artistic medium. Creativity in code may exist not only in its final visual or musical output, but also in the design of its rules, the form of its language, the use of constraints, and the process of execution. In some cases, writing the code becomes part of the artwork itself.

## Why Learn When AI Can Write the Code?

This still leaves the central question: if AI can already generate code from natural-language instructions, why should a designer learn programming?

AI will probably replace some repetitive coding tasks, but this does not remove the need to understand the medium. A designer without programming knowledge can describe a desired result to an AI system, but may struggle to understand why the result behaves in a particular way. They may also be unable to recognise the constraints, assumptions, and default decisions hidden in the generated code.

This resembles my experience of using AI for visual creation. “Create an innovative animated typography work” expresses a general intention, but it does not specify how the letters should move, what should trigger each transformation, how the composition should develop over time, or whether an unexpected result supports the intended meaning. The creator still has to define the rules and judge the outcome.

Learning programming can therefore help a designer move from describing a final appearance to designing the process that produces it. I do not need to compete with AI over who can write syntax more quickly. Instead, I need enough knowledge to communicate my intentions precisely, understand how rules shape results, and decide when an AI-generated solution should be revised or rejected.

## Understanding the Medium

I am not learning programming to prove that machines cannot be creative. I am learning it to develop a more active relationship with a medium that increasingly shapes visual culture and interactive experiences.

The internet expanded the boundaries of art, and code introduced a form of expression based on rules, time, behaviour, and execution. Even if AI writes much of the code in the future, understanding programming will still allow designers to participate in determining how a work behaves and what it makes possible. Without that understanding, I may only choose from possibilities already prepared by a tool. With it, I can question those possibilities and begin to create my own.
