# Creating Through Rules: Why I Still Need to Learn Programming

The internet has expanded the boundaries of art and given designers more media through which to create. Art is no longer limited to painting, sculpture, or photography. It can also take the form of moving images, interactive installations, generative graphics, game worlds, or even a program while it is running. For this reason, I believe that learning programming as a designer is not only about gaining a practical skill. It is also about understanding a new creative medium.

Several years ago, while scrolling through a video platform, I encountered an animated work that combined a web-like structure with typography. The letters moved and interacted with lines and space. I no longer remember the title or artist, but I still remember my reaction. I wondered which software had created the effect, until someone in the comments explained that it had been generated with code.

That moment challenged my previous understanding of programming. I had imagined code as something completely rational, technical, and closely associated with engineering. The work showed me that code could also produce visual expression, using a more logical and rule-based process. Instead of manually deciding every final image, an artist could define how letters move, how lines connect, and how forms respond to time or interaction.

## Creativity Within Constraints

Art and programming may therefore have more in common than they first appear to. Programming languages operate through strict syntax and logical constraints. Designers also work within limitations such as dimensions, materials, software capabilities, brand guidelines, and user needs. These limitations do not necessarily reduce creativity. Understanding and reorganising them can lead to new forms of expression.

In [*The Art of Code*](https://www.youtube.com/watch?v=6avJHaC3C2U), Dylan Beattie presents programming as more than a practical method for producing functional software. Through examples including Conway’s Game of Life, quines, obfuscated code, esoteric programming languages, visual programs, and algorithmic music, he demonstrates how rules, syntax, constraints, and execution can become materials for creative expression (NDC Conferences, 2020).

A program written in Piet, for example, can resemble an abstract painting. A Chef program can also be read as a recipe, while Beattie’s Rockstar language allows executable programs to resemble rock lyrics. These examples blur the distinction between a tool, an artwork, and the process used to produce it. The talk does not prove that every piece of code is art. Instead, it shows that code has the potential to become an artistic medium. Creativity may exist not only in the final image or sound, but also in the design of rules, the form of the language, and the process of execution.

## From Visual Scenes to Interactive Worlds

Another important reason for learning programming comes from my current study in multimedia entertainment. Many ideas in this field are expressed through games and interactive worlds rather than static images alone. In my own work, I have started experimenting with Unreal Engine 5 to construct game environments.

At first, building a world can appear to be mainly a visual task involving landscapes, architecture, lighting, characters, and atmosphere. However, a game world also needs behaviour. Doors must respond, objects must change, events must be triggered, and the environment must react to the player.

Unreal Engine’s Blueprint system enables designers to create gameplay through a node-based visual programming language by connecting events, functions, and variables (Epic Games, n.d.). Although its interface is visual, it still requires computational thinking. I need to understand cause and effect, conditions, sequences, states, and interaction logic. Without some knowledge of programming, I may be able to construct an attractive scene, but I will struggle to make it function as a coherent interactive world.

Learning art and technology together helps me respond more flexibly when problems arise. It allows me to consider visual experience and technical feasibility at the same time, instead of treating them as unrelated stages. Interdisciplinary ability does not mean mastering every field alone. It means recognising what kind of problem I am facing, communicating across disciplines, and connecting different forms of knowledge. This can create more efficient solutions while opening unfamiliar and interesting areas for exploration.

## Why Learn When AI Can Write the Code?

If AI can already generate code from natural-language instructions, however, why should a designer learn programming? AI will probably replace some repetitive coding tasks, but this does not remove the need to understand the medium. A designer without programming knowledge can describe a desired result, yet may struggle to understand why it behaves in a particular way or recognise the assumptions hidden in the generated code.

This resembles my experience of using AI for visual creation. “Create an innovative animated typography work” expresses an intention, but it does not specify how the letters should move, what should trigger each transformation, how the composition should develop over time, or whether an unexpected result supports the intended meaning. The creator still has to define the rules and judge the outcome.

Learning programming therefore helps me move from describing a final appearance to designing the process that produces it. I do not need to compete with AI over who can write syntax faster. I need enough knowledge to communicate my intentions, understand how rules shape results, and decide when an AI-generated solution should be revised or rejected.

## Understanding the Medium

I am not learning programming to prove that machines cannot be creative. I am learning it to develop a more active relationship with a medium that increasingly shapes visual culture, games, and interactive experiences.

Even if AI writes much of the code in the future, understanding programming will allow me to participate in determining how a work behaves and what it makes possible. Without that understanding, I may only choose from possibilities prepared by a tool. With it, I can question those possibilities and begin to create my own.
